# 棋谱回放器：需求交代

> 2026-09-29 用户提出，交给一个独立的后台会话负责，用户直接和该会话交互。本文是交代材料，定下的方案另写进 `docs/viewer.md`（由负责会话创建）。

## 目的

模型对模型的对弈棋谱要可视化播放，截屏录成视频，发到社交账号。另外，用户自己也要能回放棋谱，逐步看每步的元信息和理由。

## 选型顺序（用户定）

1. 现成可用的平台（网页服务、网站）能满足需要，最好。
2. 次选现成的开源项目。
3. 确实找不到合适的，才自己做，或基于开源项目修改。

首选 web 版，方便 agent 用浏览器自动化录屏。非 web 的桌面软件也可以考虑，但要说清在 Mac 上录它的代价。中国象棋和国际象棋可以用两套不同的东西。

## 用户明确的需求

1. 能加载多个棋谱，连续播放，一盘播完自动接下一盘。
2. 按固定间隔自动走子，默认每步 2–3 秒，可调。
3. 能展示每一步的元信息，包括评注，也就是模型写的这步的理由。
   - 录屏时隐藏：手机上不好读，2–3 秒一步也来不及看。
   - 用户自己回放时要显示，供阅读。
4. 用第三方的东西时，两种棋分开用也行。

## 主线整理的补充需求（待与用户确认、可增删）

- **录屏模式可自动化**：能用网址参数或脚本直接进入「隐藏元信息、自动播放」状态，并能知道何时播完，让 agent 用无头浏览器录制，不靠人点。时间节奏要稳定，不因加载卡顿丢步。
- **画面比例**：社交平台常见竖屏 9:16 和横屏 16:9，能按比例出干净画面，清晰度够（高 DPI）。
- **盘面信息**：双方是谁（模型名加思考深度）、执哪方、当前第几步、上一步高亮、被将军提示、终局结果和结束原因。每盘开头最好有一张标题画面。
- **记谱显示**：中国象棋用中文记谱（如「炮二平五」），国际象棋用标准记谱。
- **回放模式**：能暂停、前后单步、跳到任意一步；每步显示理由、耗时、思考 token、输出 token、非法重选次数。
- **数据留在本地**：棋谱不必须上传第三方；如果选第三方平台，要说明上传了什么。
- **许可**：用开源项目时，按仓库 AGENTS.md 的许可政策过一遍（强 copyleft 那一族的边界问维护者，别自己下结论）。

## 棋谱现状

- 国际象棋：`runs/<tag>/game.pgn`，标准 PGN；每步评注里有 `[%emt h:mm:ss]`（标准耗时命令）和自定义的 `[%think N] [%out N] [%in N] [%cacheread N] [%cachewrite N]` 等，后面接棋手写的理由文字。评注里的 `{ } %` 已换成全角。
- 中国象棋：`runs/<tag>/record.txt`，程序自己的文本格式，每步元信息照 PGN 评注的写法自定义。可能需要转成某个通行格式（如 xqbase 规范的中国象棋 PGN、FEN 加 ICCS 着法）才能喂给现成工具，转换器可以写在本仓库。
- 格式说明：`docs/design.md` 第四节（记录格式）和第九节（真实棋手协议）。
- 样例：`runs/g1-c-opus-sol/game.pgn`、`runs/g1-x-opus-sol/record.txt`。另有两局国际象棋 opus 对 astra 正在下，结果会在 `runs/g2-c-*`，带理由文字。
- `runs/` 被 git 忽略，只在本机。

## 约束

- 本仓库只在本地，没有远端，不推送。
- 别动 `runs/` 里正在下的对局和它们的进程。
- 代码放哪里（本仓库子目录，还是 `~/repos/` 下新开一个仓库）先跟用户定。
