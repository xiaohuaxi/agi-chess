# 历史本机录屏经验（2026-09-29）

这份调研总结本项目阅读器开发前的三组本机录屏材料：两组浏览器对局视频和一组单窗口录制测试。依据是当时的私人原片、工具源码、会话记录及平台显示测试；它们不随本仓库分发，也没有可公开核验的附件。本次只整理历史观察，没有重新验证当前 macOS、浏览器或平台行为。保留原文件名以免破坏旧引用。

## 录制方法与取舍

- 前两组由 ChatGPT 桌面端操作真实 Chrome 窗口，直接把窗口拖窄，让页面自然响应式重排，没有设备模拟或 CDP Emulation。用 macOS `screencapture -v -R<x,y,w,h> out.mov` 捕获屏幕固定区域，再由 AVFoundation 脚本抽帧、截头、变速；要求窗口在可录制的屏幕区域内且不被遮挡。
- 后续测试改用自写 ScreenCaptureKit 单窗口捕获工具：窗口被遮挡时仍可录，避免录入其它桌面内容；工具支持列窗口、录制与单帧捕获，SIGTERM可正常收尾，历史码率设置为宽×高×4。该工具不在本仓库，不能直接按本报告路径调用。
- 后期使用 ffmpeg 探测、寻找空等区间、联系表抽查、剪辑和变速，目标为 H.264、30fps恒定帧率、faststart、1080×1440。比例不符时加黑边，不横向拉伸。
- 这些历史样本没有使用 Playwright、浏览器扩展录像或逐帧截图合成。单窗口录制也不能消除窗口关闭、最小化、切换桌面空间、权限与锁屏带来的失败，不能据此承诺无人值守可靠。

## 失败经验与版式选择

- 锁屏时曾录了585秒保护壁纸，而另一种 App 截图接口仍能看到棋盘。因此开录前应试录3–5秒并打开成片核实，不能拿App截图代替录屏结果检查。
- 9:16样本在当时小红书App的手机显示中被放大铺满、左右各裁约4.5%，浮层可能遮住底部约12%；比例尺视频测试后采用3:4、1080×1440。3:4当时按屏宽完整显示，上下黑边容纳作者名与标题浮层。这些是历史本机观察，不是平台公开规格或跨版本保证。
- 直接录制棋手操作的标签页会把agent光标、提示框和调试条带进画面；单独开只显示棋局的录像窗口可以减少这类叠加，但窗口被关闭也曾造成中断。
- 思考期间画面长时间静止，需要变速或剪掉空等；真实录制的速度、抖动和失败都会进入视频。
- 调窄真实窗口虽然能自然重排，但可能挤掉评注等信息。内容区、浏览器外框与目标比例应分别核验，出片前检查账号及本机路径是否露出。

## 对本项目的技术意义

实时单窗口录制比固定区域录屏更少受遮挡影响，适合确实需要保留桌面软件界面的场景；仍需权限与窗口状态检查。棋谱阅读器已经知道每步状态和结束时刻，可以直接控制动画进度逐帧出片，避免依赖实时棋手操作和长时间空等，版式也能只保留内容区。

当前出片方案及测试依据见[阅读器设计](../viewer.md)和[录制技术调研](recording.md)，实际使用见[阅读器指南](../viewer-guide.md)。历史经验只解释取舍，不作为当前操作脚本或平台行为的保证。
