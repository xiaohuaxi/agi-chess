## 核对方法

对每次作答比较完整原文的最终明确着法、当时记录的 `move_text`、`attempt.move` 与随后实际落子事件。
独立复核另从原文物理末行起算，避免只拿程序已提取的文本反过来证明程序正确。
不把理由中的候选、变化或对手着法当成当前落子，也不从合法着法表猜测模型想走哪手。

- 中国象棋用 pyffish 按实际局面重放、查合法性，并以 WXF 记谱独立对照普通中文记谱。
- 国际象棋用 python-chess 重放，独立解析最终 SAN／UCI，并核对实际动作。
- 171 盘正式公开棋谱与原始落子链逐步一致，共 17,677 半回合：中象 7,170、国象 10,507；其中还含引擎与程序代走的开局，不能当成模型步数。
- 中象普通中文记谱的独立 WXF 对照覆盖 7,095 半回合；另 75 步涉及前后等复杂消歧，未强行验证 WXF 等价关系。这些步的原始最终坐标与记录、落子仍一致。
- 正式局面题的 2,779 次非空原答与 1 次空答共 2,780 次尝试，原始结果与 28 份已跟踪 `judged.jsonl` 的 2,684 条结果逐项吻合。

当时行为以原始日志为证，不能用当前解析器重跑代替历史实现。
国象历史提取器可按提交复核 6,459 次尝试；一个临时提交缺失，另有 dirty 版本不能从基准提交完整还原。
这些限制不影响已完成的原文、存储文本与实际落子链核对。

## 已确认的历史提取错误

正式 `runs/b1/maia-1900-s3-w`，第 45 半回合，运行提交为 `11332a7`。
模型先给出不完整的 `e3`，随后明确更正为 `g3e3`（Qe3）；python-chess 在真实局面确认该手合法。
旧提取正则在前一行“着法：”之后跨行吞入下一标签，得到带标签的 `着法: g3e3`，因此误拒绝。
程序重问要求换一步，模型改答 Qc3，实际落子为 `g3c3`。

影响包括多记一次非法、消耗一次重试与额外调用，以及本次实际选择改变。
本盘最终在第 113 半回合三次重复和棋；本审计没有做反事实棋力分析，不能推断原先走 Qe3 后仍会和棋或会改变胜负。
这是旧 xhigh／stateless／legacy B1 基线中的真实过程偏差，不是只影响非法计数。
该盘不在最终 Max 国际象棋 30 盘 `zc` 样本，也不进入该评级拟合；选择范围可核对 [评级脚本](../analysis/rating/rate.py)与[定位报告](results/opus-max-rating.md)。

提交 `a363108` 已修复跨行吞标签并保存回归测试；同一原答现能提取 `g3e3`。
[旧 B1／C 报告](results/batch2-chess-strength.md)已记载此事件；原有“未修”状态及“只多记一次非法、不影响结果”的判断已在其解析 bug 小节更正，原统计数字与比分保留。

## 结论限制与证据保存

当前解析对同时含中文记谱与坐标的文本采用前缀，未核对后附内容。若协议约定前面的着法是指令、括号只是说明，这种处理本身可以成立；此前直接把“不检查括号”定性为 bug 过强，更准确的问题是取值边界尚未写清。它与已经确认的旧 B1 跨行吞标签错误不是同一件事。
另已复现多位数字截断、同一行改口及中英文标签改口的解析缺口；这些输入没有在本次已审正式历史的最终着法行中触发。“历史未发现”不等于“解析器没有漏洞”。
新 Linux 冒烟中的输入只是诊断样例，不计入正式历史样本。

此次没有修改棋规、提示、解析代码或历史原始结果，也没有重估等级分。
核对不覆盖模型隐藏思考、未记录调用、所有自然语言解释或长将长捉历史裁决；不能由此重新证明全部棋力研究结论。
现有证据不足以因“程序把最终明确走法下错”而重算全部正式对局，但旧 B1 过程偏差应在引用该基线时保留。

完整源清单、哈希、离线脚本、逐步结果与独立复核保存在仓外审计证据包，原始答复和临时对局不入库。
新 clone 可阅读本报告与公开棋谱，但缺这些未入库原始记录，无法完整复算本次原文审计。
实验条件及历史报告入口见[研究索引](research.md)；本报告只补充解析影响范围，不改写旧实验条件。


## 后续改进（暂缓）

2026-11-10 用户决定：记录为后续工程改进，未来改用 JSON 结构化回复，当前不实施，也不继续叠加括号或理由正文的语义校验。

方向是把唯一落子指令与可见理由分开，例如 `{"reason": "出马控制中路", "move": "h9g7"}`。程序只从 `move` 读取一个坐标着法（中国象棋 ICCS、国际象棋 UCI），`reason` 用于记录和展示，其中的候选、坐标或记谱不参与决定实际落子。JSON 格式有效仍不等于着法合法，现有棋规检查仍需保留。具体 schema、各通道支持方式及旧记录兼容在实施时确定，不把这个示例当作已经支持的协议。

此方向用于明确字段边界、简化解析，不保证服务商不再拒答。正常棋手理由是可见的走子说明；换成 JSON 不会自动改变请求的含义，也没有证据证明它能消除对索取内部思考的误判，更不能把先前的拒答原因直接等同于“服务商认为在蒸馏”。未来仍沿用既有拒答停止规则，本次不做真实模型拒答探测，也不将 JSON 当作绕过防护的方法。
