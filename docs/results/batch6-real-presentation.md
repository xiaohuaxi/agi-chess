## 一句话结论

**两种棋的默认给法都维持不改：中国象棋只给子力清单（pieces），国际象棋 FEN + 字母棋盘（all）。** 新协议下 opus 在中国象棋上仍是 pieces 最好，「谁能吃到谁」类昏招对 all 8 个局面变好、0 个变坏，过了「有效方向」门槛；sol 在三档之间完全分不开（大失误 28–31%），没人在 pieces 下吃亏，分不开就挑最简单的，仍是 pieces。国际象棋 opus 的 all 点估计反而比 board 好（大失误 44% 对 57%，没到门槛），没有换的理由。**不报将军之后没看到变差**：两种棋各只有一个被将军的局面（x2-07、c2-15），新协议下 opus 在这两题上没有首答非法、大失误比旧协议还少；sol 在 x2-07 上大失误多了（4/6 对旧 2/6），但只有一个局面、首答非法反而少了，而且它唯一的非法着法是旧协议下也出过的同一个错，看不出是少了将军提示造成的。

- 首答非法整体上也没变多：新协议下 opus 共 10 次、sol 3 次，全是蹩马腿、越子、塞象眼、帅斜走这类走法没套对，**没有一次和被将军有关**（没有「送将」或「没解将」的非法着）。

## 判定

标准同第四、五批：没有哪一家在这种给法下明显吃亏；分不出高下时挑最简单的。

- **中国象棋：维持 pieces。** opus 下 pieces 仍是三档里最好的，「谁能吃到谁」对 all 过门槛；sol 三档分不开，pieces 下没吃亏；pieces 最短（第四批统计的局面段字符数中位 124，all 649；新协议只去掉了清单里的子数）。被将军的题上 pieces 也不比别的档差。置信度：只能看方向（opus 每题 3 遍、sol 2 遍）。
- **国际象棋：维持 all（FEN + 字母棋盘）。** opus 下 all 点估计比 board 好（2 好 5 坏，没到门槛）；第四批不换 board 的理由（字母棋盘没有易位权和吃过路兵信息）照旧成立。这批只有 opus 的数据，sol 没跑国际象棋。置信度：只能看方向。

## 局限

- **样本少**：opus 每题 3 遍，sol 每题 2 遍；被将军的局面两种棋各只有一个。
- **sol 没跑国际象棋**，DeepSeek 没跑，国际象棋的判定只靠 opus。
- **回复只剩一行着法**，没法像第四、五批那样从正文查「某子在某格」读错，只能看首答非法；记录里也没有思考原文。
- **程序问题（没改，报给父级）**：sol 跑批时 codex 事件流里出现了 `type: error` 的传输提示——「Falling back from WebSockets to HTTPS transport. stream disconnected before completion: Connection reset by peer」和「... request timed out」——程序把它当成「用了工具」抛异常，整个 run 直接退出（7d3a4ab 只放过了重连提示，没放过这两条）。两次都在 codex 自己换 HTTPS 重试之后，不是真用了工具。续跑能补齐，但每崩一次，在飞的几题（这批约 6–10 题）已花的额度白费。局面题的 sol / DeepSeek 都走这条 codex exec 旧路，以后再跑会被同样打断（整盘新协议走 llm-chat，不经这段解析）。
- 只有 high，结论不能外推到更深的思考档。
- 新旧协议的并排不是同条件对比，只作参照。
- 选定的给法只在局面题上验过，整盘对局里的效果还没测。
