# 能吃未吃 / 白送未被吃：是没看到，还是有意不吃；基础设施能不能改善

- 日期：2026-09-29 至 09-30。对象：新协议整盘对局（`runs/g2-*` 到 `g5-*`，17 盘；g5-x-astramax-opus-1 当时还在下，没算）。棋手 opus 和 astra（gpt-6-astra），重问都用 xhigh（C5 那一格实战是 astra max，按实战用 max）。
- 办法：不下整盘，只在出问题的那一步重问：把实战会话复制一份、截到这一步之前接着问（「截断重问」），每遍都是独立的新分叉；只改一个条件，看漏吃少没少。
- **局面是专门挑的失败点，同一例的几步、同一局面的几遍都不独立，每格 4–6 遍。下面所有数字只能看方向。**

## 一句话结论

**这类错几乎都是没看到，不是有意不吃**：14 例里 13 例理由没提、或提到了那个子却没想到能吃；同一截断点问「现在有哪些合法吃子」，26 次全都列出了那步吃子，一个错的漏的都没有——规则和读盘都没问题，是下棋时没往那儿看。**只改局面给法（按纵线列子、加字符棋盘、上一步写明子名、国际象棋加子力清单）和系统提示讲全规则，都没有明显改善。唯一明显起作用的是：opus 续接会话时不带此前各步的思考**（可见的理由和着法照带），吃到的遍数从 16/84 升到 44/84，国际象棋那例后被兵吃的局面 0/18 → 16/18；普通局面上没看出变差，输入 token 还少到约五分之一。但 opus 测到的 7 个吃子例子（开局那种三盘各算一个）里只改善了 3 个，开局那种（第 7 个半回合车吃炮）怎么都不吃。astra 换新会话在国际象棋上有一点方向（17/28 对 7/28），中国象棋「炮隔炮打车」怎么改都几乎看不到（新会话 3/24，原样 0/24）。

## 2. 判定：没看到还是有意不吃

判法（和 astra 一起定，见文末）：引擎核实吃子真赚；读理由（理由不提只算「未提及」，不单独当证据）；截断重问看能不能复现；同一截断点换成诊断问法看它能不能认出这步吃子。诊断问法只用于判定，不进对局协议。

挑 16 个局面（中国象棋该吃 8、白送 2；国际象棋该吃 4、白送 1、该救 1），每个原样重问 4 遍；该吃 / 该救的局面再在同一截断点把「请走一步。」换成「这一步先不走棋。请列出现在轮到你走的一方所有合法的吃子着法……没有就写『无』」（不点名子和格），各 2 遍。

| 结果 | 局面 |
|---|---|
| 诊断问法：26 次全部列出目标吃子，每个局面的合法吃子都列全（最多一局 9 个），错列、漏列都是 0 | 全部 13 个该吃 / 该救局面 |
| 原样重问稳定不吃、理由不提 | X1、X7、X8（astra 炮隔炮打车 / 打中卒），X3、X4、X5、X6（opus），C1（opus 兵吃后），C4（astra），H4（astra 4 遍全部重走 Qe6 白送后） |
| 时看时不看 | X2（实战漏、重问 4/4 都吃）、H1、H5、C3、C5 |

- **规则、读盘都没问题，是注意力**：一问就全列对；原样下棋时，凡是理由里说到「能吃 / 会被吃」的那几遍都照着做了，漏的那几遍理由一句不提。**「看到了、权衡后不吃」在全部重问里一遍都没出现**，只有实战第 8 例一次。
- 典型样子：opus 在 C1 整段理由围着 e6 的黑后转，还写「d5 兵其实是间接有保护的」，只把 d5 兵当成被后攻击的对象，没反过来看兵能吃后；astra 走 Qe6 的理由是「瞄准 d5 兵」，也是只看一个方向。astra 漏的那几遍思考只有十几到几十 token（C3 吃到的那遍 605）。
- 所以 13 例按「没看到」处理，下面的实验都针对它们。

## 3. 基础设施变体

哪些算「通用基础设施、不算协助」，和 astra（Codex，high，只读）一起定的：

| 变体 | 判定 | 这次测没测 |
|---|---|---|
| 局面给法换档（加字符棋盘；国际象棋加子力清单） | 可以 | 测了 |
| 按纵线重排的子力清单（每条纵线从红方底线列到黑方底线，不标炮架、不标可吃） | 可以 | 测了（只替换 / 原清单加纵线两档） |
| 国际象棋上一步写明子名（「后 d8→e6」，不写吃、不写将军） | 可以 | 测了 |
| 系统提示讲全各子走法吃法（各子平铺，不单独强调炮架） | 可以 | 测了 |
| 每步新会话（给局面 + 此前全部着法，系统提示去掉「同一段连续对话」那句） | 边界：会话机制实验，单独比可以 | 测了 |
| 续接时不带此前思考（可见理由和着法照带） | 同上，会话机制 | 测了（opus） |
| 一般性自查提醒、强制先复述局面 | 边界：教它怎么想，不算纯基础设施 | 没测（第二批已测过自查） |
| 威胁高亮、可吃目标排序、吃子关系图、按局面触发提醒 | 协助，不可以 | 不测 |

opus 换系统提示或改写此前的对话时，服务端会把此前的思考块整个丢掉（记录里核实过每一遍）。所以另设了一个对照 **noop**：系统提示原文末尾只加一句「祝对局顺利。」，效果就只是「丢掉此前思考」。第三阶段再直接做了**剥思考（strip）**：分叉出来的会话记录里删掉此前所有思考块、其余逐字不变。

## 4. 建议

1. **给法和规则说明不改**：按纵线列子、加棋盘、上一步写子名、国际象棋加清单、系统提示讲全规则，都没有明显改善，有几格还变差，维持现在的默认。
2. **opus「会话里只带可见文字、不带此前思考」值得当候选**（改默认要用户拍板，这里只建议）：漏吃局面上方向明显，普通局面没看出代价，上下文还小很多、更省。但证据只有 7 个例子、改善的只有 3 个，全是挑出来的失败点；它又和 9/29 定的「每方一个会话连续下」、以及「思考延续是核心变量」的假设直接相关。建议先下几盘对照（例如 opus 对 astra 两种棋各 2–4 盘，一方剥思考），看整盘大失误率和胜负再定。实现要在每轮续接前改 claude 的会话记录（去掉思考块），llm-chat 脚本现在做不到，需要加开关或在程序里处理。
3. **astra**：国际象棋每步新会话有一点方向，但复核没站稳；中国象棋没有找到能改善的基础设施。暂不改。
4. **白送（自己把子送到嘴边）**：opus 的白送车（H1）剥思考前后都是 4/6；astra 白送后（H4）只有新会话 3/4。样本太少，不下结论。

## 样本与局限

- 局面是专门挑的失败点，又集中在 g4-x、g4-c 几盘里；第 2、4 例各贡献了好几个局面，按例子算 opus 7 个、astra 7 个（都含同一开局或同一盘的几例）。
- 截断重问能测「在同一处再来一次会不会重犯」，不能还原当时那一次的心理过程；opus 分叉的运行目录和实战不同，每次多一句「工作目录变了」的环境提示。
- 诊断问法「列出所有吃子」本身就是在引导它检查吃子，只能证明「被要求时能认出」，不能证明实战里看见过。
- 理由有没有提到目标是逐遍读理由人工判的；失败遍在第二阶段只细读了一部分。
- 非法首答：第二阶段 288 遍里 8 遍，基线 64 遍里 1 遍，分散在几个条件里，看不出归哪个变体。
- C5 一格按实战用 astra max，其余 xhigh。
