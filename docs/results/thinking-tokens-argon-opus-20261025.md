# 国际象棋每步思考 token：Argon High、Opus 与 Astra（2026-10-25）

**现有整盘记录里，Argon High 的思考量更接近旧 Opus xhigh，而不是 Max。旧 Opus Max 对 Astra Max 四盘，Opus 每步均值是 Astra 的 6.53 倍，中位数是 9.82 倍；这是上报 token 的差距，不是算力或棋力倍数。它支持“不能把 Argon 战胜 agy Opus High 当成战胜旧 Opus Max”，但不能验证上一轮约 100 分的主观差距。**

本次只离线读取既有配置、用量元数据和已有复盘结论，没有调用模型、重跑引擎、读取或还原隐藏思考。全部主表均为国际象棋；数字来自原始 `game.jsonl` 重算。

## 口径与前提

- “每步”是该棋手的一次落定着法，使用 `move.stat.think`，含同一步非法重选、空回复等已记账调用。不是只拿最后一次成功回答。每组按所有步合并，均值按步数加权，中位数不平均逐盘中位数。
- 逐步核对 `attempt.usage.think` 合计等于 `move.stat.think`；并逐盘复核末尾 `end.summary` 的思考总量与中位数一致。对缺失用量，额外查原始 META / usage 字段，避免转换层把 null 填成 0。
- 有效用量步要求本步所有 attempt 都有数值思考字段；缺一条则整步不进完整分布。真实报告的 0 保留，但 agy Opus 的全 0 是否代表真实思考量尚未核实，因此单列，不拿来排名。
- p90 使用最近秩法：排序后第 `ceil(0.9×n)` 个。长尾前 5% 使用最大的 `ceil(0.05×n)` 步。第16手起指实际棋谱 `ply > 30`，不是模型第16次调用；这里只去开局，**没有排除已分胜负的后半盘**。
- 已核实：Argon / agy Opus 的配置、原始用量缺失位置；旧 Opus 成功调用的服务端型号均为 `claude-opus-5-5`；旧 CLI 整盘的会话、档位和整步统计。未核实：agy Opus High 的底层 thinking_budget、与旧 CLI High 的预算等价、跨厂商 token 与计算量的换算。结论不依赖这些未核实项。

## “Opus Max 远超 Astra Max”到底有多大

同四盘、双方都是Max：

- Opus178步总计1,280,710；Astra177步总计195,031。按步数均值是7,195.0对1,101.9，**6.53倍**。
- 中位2,131.5对217，**9.82倍**。这是两边分布中位数之比，不是逐局面配对的token倍数。
- 第16手起均值10,602.2对1,647.3，**6.44倍**；中位5,561对1,051，**5.29倍**。Astra开局大量低思考步压低了全盘中位数，去开局后“近十倍”缩为约五倍，差距仍在。
- 按单次已记录调用算，Opus179次均值7,154.8、中位2,151；Astra177次均值1,101.9、中位217。主结论不是Opus多一次非法重选造成的。

对应旧报告把中位数四舍五入为2,132 / 217，本次复算一致。旧Opus xhigh对Astra Max是均值1,311.6、中位448；不同四盘中Opus Max约为其5.49倍均值、4.76倍中位。对手虽然同是Astra Max，局面并不相同，因此这里只描述用量差距，不把它全归因于调档。

## 对棋力判断有什么用

这些数值让“Argon High胜了agy Opus High，所以应当接近或超过旧Opus Max”的推理更站不住：当前agy Opus的实际思考用量不可观测；而Argon可观测量通常在旧Opus xhigh的范围，旧Max在同类整盘确实多用数倍token。**维持略看好旧Opus Max是合理的工作假设，但token数据本身不支持把差距定成100分，也不支持据此扩大差距。**

已有质量证据同样要求克制：Argon对agy High四盘3:1，但ACPL44.7 / 53.3，去开局和已分胜负阶段后65.6 / 76.1，且开局重复。旧Opus Max对Astra Max四盘3:1、ACPL47.0 / 58.0，但两个白方开局前43半回合完全一样；最大思考步121,664本身还是一次大失误。更多token既可能伴随更认真计算，也可能表示局面困难、反复推演仍没找到正确答案。

档位与表现的正面关联来自旧同题High→Max解中率65%→88%等证据，不等于“每增加若干token就增加若干Elo”。跨厂商分词、架构、每token计算、训练与服务端调度不同；token既不等于FLOPs，也不等于相同预算、有效搜索深度或棋力。之前Argon约Blitz1700 / Rapid1800、Opus Max约高100分的说法，仍只能是结合既有棋局与评级锚的主观估计，不能称为本次token分析验证的评级。

## 计量来源与复算

旧CLI Claude从 `usage.output_tokens_details.thinking_tokens` 取数；llm-chat把它映射为 `meta.reasoning_tokens`，项目 `llmchess/chat.py:140` 再映射为 `think`。Codex一路由 `reasoning_output_tokens` 映射，连续会话由llm-chat先按累计用量做差；历史[会话诊断](thinking-in-session.md)逐轮核验过此口径。`llmchess/records.py:116` 的可用性判定要求看原始字段，`runner.py` 在每次attempt之后累加统计。因此本报告统计的是后端返回的计量，不是从隐藏文本重新分词，也不代表后端未报告的计算。

原始组：

- 自弈：`runs/argon-high-chess-self-20261019`。
