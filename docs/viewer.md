> 2026-09-29。需求见 `viewer-brief.md`，调研证据在 `viewer-survey/`（看过哪些项目、为什么不用：`viewer-survey/README.md`）。
> **状态：方向已由用户定（自己写、放本仓库）；按第二轮对齐改写，过了一轮方案审查（三路，含 Codex），审查意见已并入。待用户确认后实施。**

## 一句话

在本仓库写一个本地网页棋谱阅读器。它读棋谱文件本身（国际象棋标准 PGN，中国象棋照 xqbase 规范的 PGN），认得我们自定义的评注命令，普通人的棋谱也能播。宽窗口时显示评注和元信息，窄窗口时只剩棋盘。录屏由脚本驱动页面逐步截图、拼成 mp4。

## 已定（用户 2026-09-29）

- 自己写，放本仓库，作为一个工具；先把模型对弈用得上的功能做好，普通棋谱能播即可。
- 走子滑动动画可选，有难度先不做。标题画面先做，最终用不用再议。录屏时显示当前这步的记谱，可以用开关关掉。
- 大失误等判断由 agent 写进对应那步的评注，阅读器只负责显示。
- 录屏走脚本出片（前提：写 / 测代价不高，评估见下）。出片格式 mp4 + H.264。
- 录屏画面：一行横向元素尽量少；看得出谁执哪方；不写棋种；显示思考 token（写成「累计 +本步」）；棋盘外空间按 3:4 算好（具体摆法见「录屏画面」一节，待用户看过打样定）。模型名全小写，如 `opus+xhigh`。
- 中国象棋棋谱用 xqbase PGN + 中文记谱，要能带每步棋评等元信息，以后给网站看盘用。
- 调研过、没采用的项目记在 `viewer-survey/README.md`，克隆已删；留下 cm-chessboard、chess.js、pgn-parser、xiangqi-setup、vschess 五个备查（vschess 是 LGPL，只参考思路、不抄代码）。

## 做成什么样

**输入是棋谱文件。**
- 国际象棋：标准 PGN，一个文件里可以有多盘。
- 中国象棋：xqbase「中国象棋电脑应用规范」的 PGN（原文 `www.xqbase.com/protocol/cchess_pgn.htm`、`cchess_move.htm`）。要点：`[Game "Chinese Chess"]` 放第一个标签；双方标签是 `Red` / `Black`；`Format` 不写默认是中文记谱；黑方数字用全角「１２３」，同线第几个兵的「一二三」仍用汉字（如「一卒平５」）；同一纵线上有多个同种子时用前 / 中 / 后或一二三四五区分，两条纵线都有多个兵另有编号规则（审查摘录和网页摘要的说法有出入，实施前对照原文逐条定）；仕、相同线不写前后，靠进退区分。读别人的棋谱时容错半角数字、繁体字（俥傌砲後進）、GBK 编码（解码失败回退 `gb18030`）。
- 评注里的 `[%emt]` 显示成用时；自定义的 `[%think] [%out] [%in] [%cacheread] [%cachewrite] [%illegal] [%flagged] [%empty]` 显示成带中文标签的数字；不认识的命令原样列出，后面的文字当理由显示。着法后的 `?` `??` `!` 等标注照常显示。
- 标签里的 `WhiteEffort` / `BlackEffort`（中国象棋 `RedEffort` / `BlackEffort`，本项目自定义，见下文导出）显示为思考深度；别人的棋谱没有就不显示。

**打开方式。** 页面是普通静态文件、不用构建，第三方库放 `viewer/vendor/`（附来源和许可文本）。浏览器不许 `file://` 下加载模块脚本，所以**只支持经本机静态服务打开**：在仓库根目录 `python3 -m http.server --bind 127.0.0.1 8000`（绑本机，不暴露到局域网），打开 `http://127.0.0.1:8000/viewer/`。选棋谱两种方式：网址参数（`?files=/runs/a/game.pgn,/runs/b/game.pgn&gap=2.5&autoplay=1`，路径按站点根解析），或把文件拖进页面。棋谱不出本机。

**版式。**
- 宽版（自己读棋谱用）：左边棋盘，右边着法列表和当前这步的评注、理由、用时、token、非法重选次数。能暂停、前后单步、点着法跳到任意一步，有键盘快捷键。
- 窄版（录屏用）：右侧整块不渲染，只剩页头、棋盘、页脚，细节见下一节「录屏画面」。
- 默认按窗口宽度自动切换；参数 `layout=compact` 强制窄版（录 16:9 时页面宽 960，自动判断会判成宽版，所以录制脚本总带这个参数）。
- 两种版式都有：上一步高亮、被将军提示（国际象棋在王的格子上加 cm-chessboard 自带的红色标记）、终局结果和结束原因、可选的标题画面（参数 `title=0` 关掉）。

**播放。**
- 自动播放（给人看、也给实时录窗口的备选用）：每步间隔默认 2.5 秒，可调；一盘播完放结果，再接下一盘；全部播完在页面上置「已播完」标记。
- 录制模式（给脚本用，参数 `rec=1`，隐含 `layout=compact`、关掉计时器）：
  - `window.viewer.ready`：字体、棋子图、所有棋谱都加载完才兑现。
  - `window.viewer.next()`：前进一格，画完（再等两帧）才返回 `{kind, hold, anim}`——`kind` 是 `title` / `move` / `result` / `end`，`hold` 是这一格该停几秒，`anim` 是走子动画的时长（没有动画为 0）。
  - 标题、结果画面停多久也由页面按参数给出，脚本只照 `hold` 办，不自己算。

**棋盘。**
- 国际象棋：cm-chessboard 画棋盘（MIT，源码是相对路径引用的 ES 模块、无依赖，可直接放 vendor；已实测按网址参数读 g1 棋谱走完 95 个半回合、2 倍截图清晰）；chess.js 按记谱走子、判将军（BSD-2-Clause，用 npm 发布包里的单文件 `dist/esm/chess.js`，本机克隆只有 TS 源码不能直接用）。
- 中国象棋：自己画 SVG 棋盘，棋子取 xiangqi-setup 里 CC0 的纯路径 SVG 素材（不含文字，不受字体影响；逐个文件核实许可）；自己写中文记谱解析（结合当前局面认出是哪个子）和将军判断，只为显示，不校验合法性。
  - 这是有意的例外：项目规定「规则判定照搬旧实现」，那是指对局程序判定输赢和合法性。阅读器只画面上提示「将军」，不影响任何结论，所以用 JS 自写；正确性靠与 `game.jsonl` 里（pyffish 判出的）将军标记逐步对照来保证。
- 两边共用一个自己写的 PGN 分词器（标签、着法、评注、标注、结果；变着先跳过不显示）。PGN 结构简单、规范写死，约一百行，比引一个只认国际象棋记谱的解析库省事。
- 走子动画：中国象棋自己写，用 CSS / Web Animations（可以按进度定格，逐帧截图能录出滑动）。cm-chessboard 自带的动画是 `requestAnimationFrame` 手写的（已读源码），不能定格，录制时关掉它的动画；国际象棋要滑动的话在上层自己补一段，列为可选、放最后。

## 录屏画面（窄版）的版式

录屏以脚本出片为主，这个画面就是发出去的成品，要单独打磨。按 3:4、1080×1440 设计（页面 540×720，2 倍像素；下文尺寸都是页面像素）。9:16 结构不变、多出的高度分给上下两条；16:9 暂不专门设计。

**用户要求（2026-09-29）**：一行里横向元素尽量少，模型名可能很长；要看得出谁执白 / 黑 / 红；不用写棋种（棋盘一看便知）；要显示模型的思考 token，累计的和这一步的，放在离棋手近、显眼的地方；棋盘外的空间要按比例算好；手机上看得清、字不用很大。

**结构：棋手条 + 棋盘 + 棋手条**（国际象棋直播、lichess、chess.com 的通行摆法）：

```
┌────────────────────────────────────┐
│             第 2 局 · 共 3 局            │  顶部细条（24）：小字弱色，单盘时不显示
├────────────────────────────────────┤
│ ● astra+max                       1 │  上方棋手条（76）：执黑的一方
│   22... 马８进７                  思考 38k │
├────────────────────────────────────┤
│                                    │
│             棋  盘（544 高）           │
│                                    │
├────────────────────────────────────┤
│ ○ opus+xhigh                      1 │  下方棋手条（76）：执红 / 白的一方，轮到走棋时点亮
│   23. 炮二平五 将军          思考 52k +3.4k │
└────────────────────────────────────┘
```

- **谁执哪方**：棋手条贴着自己那一方的棋子——执黑的在棋盘上方，执红 / 白的在下方（棋盘固定红 / 白在下）；名字前再加一个小圆片（红 / 黑 / 白）。位置加颜色双重提示，不用写「执红」这样的字。
- **每条两行，每行只有左右两样东西**：
  - 第一行：圆片 + 「模型简称+思考深度」（24，`+xhigh` 弱一档颜色）……右端本场比分（28，粗体，单盘时不显示）。名字太长时从名字中间省略，思考深度和比分不截。
  - 第二行（16–18，弱色）：左边是这位棋手刚走的一步（带回合数；将军时后面加「将军」小标签），右边是思考 token（见下条）。
- **比分跟着人走**：换先后时两人上下对调，比分写在各自的条上，所以不会对错人。
- **该谁走**：轮到的一方整条点亮（亮一档的底色 + 左边一道强调色竖条），另一方压暗。走完一步的瞬间：刚走的一方第二行更新成这步和这步的 token，然后对方那条亮起来。
- **思考 token 的写法**（用户定：简化、大家看得懂就行）：「思考 52k +3.4k」——前面是含这一步在内的累计，后面小一号、强调色的 `+3.4k` 是这一步想了多少。增量只挂在刚走完的那一方；另一方只显示累计。选「当前累计 + 本步增量」而不是「此前累计 + 本步」：累计是主数字，含义始终是「到现在一共想了多少」，增量做成角标样式，不会被读成要再加一次。
- **思考 token 的口径**：只显示思考 token（每步评注里的 `%think`），不含可见输出。理由：可见输出只是一句理由加着法，几十个 token，没什么看头；思考量才是「这步想了多少」的故事。某家后端没给思考 token 时（DeepSeek 可能不给），这一段不显示。数字超过一千用 `1.2k`、`38k` 这种写法。
- **终局**：棋盘上盖一条半透明横幅写结果和结束原因（「红方胜 · 将死」）；胜方比分加一，名字旁出一个「胜」。
- **空间怎么分**（720 高）：顶部细条 24 + 两条棋手条各 76 + 棋盘 544 = 720。
  - 国际象棋棋盘 540×540，正好占满宽度，上下各余 2。
  - 中国象棋 9 路 10 线，连边上半格余量是 9:10，高 544 时宽约 490，两边各留约 25。
  - 单盘（没有顶部细条）时这 24 分给两条棋手条。
  - 中国象棋棋盘边上要不要标路数（一至九 / １至９），打样时看：标的话上下各占约 16，棋盘略缩小。
- **字号**：视频在手机上按屏宽显示，页面 1 像素约等于手机上 0.72 个点：名字 24 → 约 17 点，比分 28 → 约 20 点，第二行 16–18 → 约 12–13 点，都不用很大就看得清。
- **底部有东西不怕被挡**：post-studio 实测，3:4 在小红书上按屏宽完整显示、上下是黑边，作者名、标题等浮层落在黑边里，不压画面（9:16 会压住底部约 12%）。
- **大小写**：模型简称和思考深度一律小写（`opus+xhigh`，用户已同意）。简称取棋手名冒号后的部分（`claude:opus` → `opus`）；不是模型的棋手（引擎、人）照原名显示。观众可能不知道 astra 是哪家，放标题画面交代（如「Claude opus 对 GPT astra」）。
- **标题画面**（可选）：双方全称与思考深度、赛制（如三局两胜），停 2–3 秒。
- 颜色、间距、字重这类审美值做出来以后截图给用户看，满意再提交，不靠文字定。
- **实施时逐项确认细节**（用户要求）：每种文字的字号、字重、行高，每行实际占多高，各块的内外边距，加起来是否正好等于 720；最长的名字（如 `deepseek-v4-pro+xhigh`）、最长的记谱、五位数的 token 放进去会不会挤；在打样截图上逐项量一遍，写进页面样式的注释里。

**比赛的概念**：连播清单就是一场比赛。第几局按清单顺序；比分按每盘 PGN 的 `Result` 累计，按人（名字 + 思考深度）归属，和棋各记半分（显示 `1.5`）。

## 中国象棋棋谱格式

象棋没有国际象棋 PGN 那样一家独大的格式，常见的几种：

| 格式 | 样子 | 用在哪 |
|---|---|---|
| 中文纵线记谱 | `炮二平五 马８进７` | 比赛记录、书籍、人读的棋谱，最通行 |
| WXF 记谱 | `C2.5 H8+7` | 中文记谱的字母版，国际上用 |
| ICCS 坐标 | `h2e2 h9g7` | 程序之间用，写起点和终点格子 |
| xqbase PGN | 照搬国际象棋 PGN 的结构，着法可用上面三种之一 | 象棋软件和网站的通用交换格式之一 |
| 东萍 DhtmlXQ、象棋桥 XQF | 网页插件格式、桌面软件的二进制格式 | 东萍网站、象棋桥等软件 |

**选 xqbase PGN + 中文记谱**，理由：中文记谱是人读的标准写法；xqbase PGN 是有公开规范的文本格式，结构和国际象棋 PGN 一样，两种棋可以共用一个分词器。

**标准本身没有歧义。** 之前说的「几个兵在同一列写不准」是本项目现在用的记谱库（cchess）的毛病，不是标准的：规范对同线多子、多路兵都规定了写法，并声明就是为了从棋局到着法完全消除歧义。所以导出端照规范自己生成记谱即可，阅读器照规范解析。

**我们要多记的东西，标准都留了口子，属于兼容扩展**（和国际象棋 PGN 的做法一样）：
- 每步理由和 token：写在着法后的 `{}` 评注里，规范说评注允许任意字符；我们的 `[%think 34]` 这类命令对别的软件就是一段普通文字。
- 思考深度：自定义标签 `RedEffort` / `BlackEffort`。PGN 允许自定义标签，读不懂的软件会忽略。

没有需要另起格式的地方。

**以后的网站看盘服务**（用户 2026-09-29 提）：棋谱要能带上每步的棋评和元信息，让网站按需组织呈现。现在的写法已经满足：每步评注里命令（`[%名 值]`，机器可读）和文字（理由、agent 加的棋评）分得开，网站可以把数字做成图表、把文字按类排版。为此要守住一条：**自定义命令的名字和含义就是对外契约**，真身在 `design.md` 第四节，新增命令（比如以后 agent 写大失误标记）先在那里登记，别各处各起名。

## 录屏：脚本出片

之前怎么录的（post-studio 调研，`viewer-survey/post-studio-recording.md`）：已发布的 007、008 是 ChatGPT 桌面端操作真 Chrome、把窗口拖窄，用 macOS 自带的 `screencapture` 录屏幕上那块区域，再剪辑。后来 post-studio 自己做了只录单个窗口的工具（`recwin.swift`）和剪辑脚本（`media.py`）。踩过的坑：锁屏时录了近 10 分钟锁屏壁纸；录像窗口被关、正式赛两度中断；agent 光标和提示条叠进画面；思考时画面长时间静止只能加速；录出来是变帧率要转码。发布比例后来定为 **3:4、1080×1440**（9:16 在小红书会被裁窄）。

**做法。** 录制脚本（Node + playwright-core，放 `viewer/record.mjs`）：
1. 自己起、关一个绑本机的静态服务（仓库根目录）。
2. 无头浏览器打开 `/viewer/?rec=1&files=…`，视口 540×720、2 倍像素（= 1080×1440；9:16、16:9 换视口尺寸即可）。
3. 等 `viewer.ready`，循环调 `viewer.next()`：静止画面截一张、记下 `hold`；有动画时把动画暂停、按 1/30 秒逐格拨进度逐格截图。
4. 写 ffmpeg concat 列表（最后一张重复写一次，否则它的时长被忽略），拼接后用 `-t` 截到应有时长（实验里末尾多出约 0.3 秒）。

**输出规格**（和 post-studio `media.py` 的默认一致，拿去剪辑、上传不用再转）：mp4 封装，H.264（libx264，High），yuv420p，30 帧恒定帧率，`+faststart`，默认 1080×1440。ffmpeg 用 Homebrew 的（Playwright 缓存里带的那个在本机跑不起来）。

**相比实时录窗口**：不用屏幕录制权限，不怕锁屏、窗口被挡或被关，用户同时用 Mac 也不受影响；每步时长分毫不差、不丢步、没有空等；画面里只有棋局；比实时快，同一盘录几次结果一样，可以批量出片。

**写 / 测代价：低，录两三次就回本。** 核心流程调研时已在本机跑通：35 行的实验脚本（`viewer-survey/record-experiment/exp_frames.js`）用 playwright-core 加本机缓存的 Chromium 逐帧截图、带走子动画，ffmpeg 合成出了 1080×1920 和 1920×1080 的 H.264 视频，两次渲染逐帧一致。正式脚本多出起服务、调页面接口、截尾，估计 100–150 行，写加测约半天 agent 时间。之后每次出片一条命令，几分钟跑完，不用人看着，不耗模型额度。实时录窗口每次都要 Mac 解锁、按实际时长干等、先试录核对不是锁屏画面、事后剪辑转码。

**备选：实时录窗口。** 页面在普通 Chrome 窗口里本来就能自动播放，post-studio 那套（`recwin.swift` + `media.py`）直接可用。脚本万一卡住就退回这条，阅读器不用改。

注：Playwright 自带的录像功能（recordVideo）不用——按网页逻辑尺寸录，放大后画面只占一角，帧率固定 25、码率低、格式 webm（本机实测，`viewer-survey/recording.md`）。

## 仓库里的配套改动（`llmchess/`）

- **PGN 标签补思考深度**：国际象棋加 `[WhiteEffort "xhigh"]` / `[BlackEffort …]`，取自 `game.jsonl` 的 `config`（双方用的深度）；非模型方（引擎、随机）不写。
- **中国象棋导出 PGN**（`game.pgn`，和 `record.txt` 并存）：标签 `Game`（第一个）、`Event`、`Red`、`Black`、`RedEffort`、`BlackEffort`、`Result`、`Termination`（沿用现在的中文结束原因）；评注写法和国际象棋一致。
  - **着法文字**：现有中文记谱（cchess 库）在多路兵、同线三个以上同种子等少见局面写不准，会在后面补「（坐标）」，出异常时直接写坐标（`llmchess/xiangqi.py` 的 `notation`）；这种写法进 PGN 就没法解析。PGN 导出改为按 xqbase 规则生成中文记谱（从局面和坐标算，只是记谱格式，不涉及棋规）；`record.txt` 保持原样，旧记录照旧复现。现有 135 盘已结束的象棋对局里一次都没碰到这类局面，所以要另造多路兵、同线多兵的局面测往返。
- **中文折行**：现在导出会在中文字中间断行，任何阅读器读回来断开处都多一个空格。改法：优先在空格或中文标点后断行，实在没有才硬切；阅读器读的时候，两边都是中文的断行不补空格。国际象棋不走 `meta_comment`，要改的是评注拆词和折行那两处（`meta_tokens`、`wrap`），两种棋共用。
- 已结束的盘用 `python3 -m llmchess export runs/<tag>` 重导（只重写导出文件，不动 `game.jsonl`）。批量重导只挑记录里有 `end` 那一行的盘，导不出的跳过并计数；别碰正在下的对局。

## 实施顺序与验证

每步做完能单独验收，后一步不依赖前一步没验证的东西。验证命令：Python 离线测试 `python3 -m unittest discover -s tests -t .`；JS 用 node 自带的 `node --test viewer/test/`（不引依赖）。

1. **导出**：深度标签、中国象棋 PGN（含 xqbase 记谱生成）、折行。验收：离线测试全过，新增测试覆盖折行、深度标签、象棋 PGN 和多路兵记谱；重导 `runs/g1-c-opus-sol`、`runs/g1-x-opus-sol`，两份都读得到双方 `xhigh`，肉眼抽查。然后批量重导本机所有已结束的对局（规则见上）。
2. **解析**（纯 JS，不碰浏览器）：PGN 分词器、评注命令解析、中文记谱解析、将军判断。验收：两份样例逐步走完、终局局面和记录一致；所有重导出的象棋 PGN 逐步走完，每步走出的坐标与 `game.jsonl` 的 `move`、将军与 `check` 一致；第 1 步造的多路兵局面往返一致（导出生成 → 页面解析 → 同一步）。读 `runs/` 的回归测试在本机没有这些数据时跳过，入库的测试只用自带的小样例。
3. **打样**（在页面外壳之前，先钉死画面风险）：装好 playwright-core，两种棋盘各出一张 2 倍无头截图，带一行中文记谱文字，看棋子清晰度和字体。
4. **页面**：两种版式、播放控制、连播、比分、标题画面、录制接口。录屏画面先做静态版式、出截图（开局、轮到上方 / 下方、将军、终局各一张，两种棋都出）给用户看，定了再接播放逻辑。验收：宽版、窄版各截一张图看；用无头浏览器调 `viewer.next()` 走完一盘、`kind` 顺序和 `hold` 对；键盘和点着法跳步手动试。
5. **录制脚本**：两种棋各出一段 3:4 视频，ffprobe 核对编码（H.264、yuv420p）、帧率（30 恒定）、分辨率、时长（各格 `hold` 之和），抽几帧看清晰度。
6. （可选）国际象棋滑动动画。
