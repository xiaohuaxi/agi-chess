## 一句话

在本仓库写一个本地网页棋谱阅读器。它读棋谱文件本身（国际象棋标准 PGN，中国象棋照 xqbase 规范的 PGN），认得我们自定义的评注命令，普通人的棋谱也能播。宽窗口时显示评注和元信息，窄窗口时只剩棋盘。录屏由脚本驱动页面逐步截图、拼成 mp4。

## 已定（用户 2026-09-29）

- 自己写，放本仓库，作为一个工具；先把模型对弈用得上的功能做好，普通棋谱能播即可。
- 走子滑动动画可选，有难度先不做（2026-09-30 用户定做：默认 0.3 秒、网址参数 `anim=` 可调、0 关掉，动画时长算在每步间隔之内、不拉长视频；已做，见「棋盘」）。标题画面先做，最终用不用再议。录屏时显示当前这步的记谱，可以用开关关掉。
- 大失误等判断由 agent 写进对应那步的评注，阅读器只负责显示。
- 录屏走脚本出片（前提：写 / 测代价不高，评估见下）。出片格式 mp4 + H.264。
- 录屏画面：一行横向元素尽量少；看得出谁执哪方；不写棋种；显示思考 token（写成「累计 +本步」）；棋盘外空间按 3:4 算好（具体摆法见「录屏画面」一节，用户 2026-09-30 定稿）。模型名全小写，如 `opus+xhigh`。
- 中国象棋棋谱用 xqbase PGN + 中文记谱，要能带每步棋评等元信息，以后给网站看盘用。
- 调研过、没采用的项目记在 `viewer-survey/README.md`，克隆已删；留下 cm-chessboard、chess.js、pgn-parser、xiangqi-setup、vschess 五个备查（vschess 是 LGPL，只参考思路、不抄代码）。

## 做成什么样

**输入是棋谱文件。**
- 国际象棋：标准 PGN，一个文件里可以有多盘。
- 中国象棋：xqbase「中国象棋电脑应用规范」的 PGN（原文 `www.xqbase.com/protocol/cchess_pgn.htm`、`cchess_move.htm`）。要点：`[Game "Chinese Chess"]` 放第一个标签；双方标签是 `Red` / `Black`；`Format` 不写默认是中文记谱；黑方数字用全角「１２３」，同线第几个兵的「一二三」仍用汉字（如「一卒平５」）；同一纵线上有多个同种子时用前 / 中 / 后或一二三四五区分，两条纵线都有多个兵另有编号规则；仕、相同线不写前后，靠进退区分。逐条规则第 1 步已对照原文定下，写在 `llmchess/xiangqi.py` 的 `pgn_move` 注释里：一线两兵前 / 后、三兵前 / 中 / 后、四五兵从前往后一至五；两条纵线各有两个以上兵时，这两条线上的兵一起编一至五，先按走棋方的纵线号从小到大（右边先）、同线从前往后，其余纵线的兵照常写（原文说明里「即先看最左边一列」与「先从右到左」和例局矛盾，以例局为准）。评注后的黑方着法照原文例子直接接着写，不补「N...」。读别人的棋谱时容错半角数字、繁体字（俥傌砲後進）、GBK 编码（解码失败回退 `gb18030`）。
- 评注里的 `[%emt]` 显示成用时；自定义的 `[%think] [%out] [%in] [%cacheread] [%cachewrite] [%illegal] [%flagged] [%empty] [%dropped]` 显示成带中文标签的数字；不认识的命令原样列出，后面的文字当理由显示。着法后的 `?` `??` `!` 等标注照常显示。
- 标签里的 `WhiteEffort` / `BlackEffort`（中国象棋 `RedEffort` / `BlackEffort`，本项目自定义，见下文导出）显示为思考深度；别人的棋谱没有就不显示。

**打开方式。** 页面是普通静态文件、不用构建，第三方库放 `viewer/vendor/`（附来源和许可文本）。浏览器不许 `file://` 下加载模块脚本，所以**只支持经本机静态服务打开**：在仓库根目录 `python3 -m http.server --bind 127.0.0.1 8000`（绑本机，不暴露到局域网），打开 `http://127.0.0.1:8000/viewer/`。选棋谱两种方式：网址参数（`?files=/runs/a/game.pgn,/runs/b/game.pgn&gap=1.8&autoplay=1`，路径按站点根解析），或把文件拖进页面。棋谱不出本机。

**版式。**
- 宽版（自己读棋谱用）：左边棋盘，右边着法列表和当前这步的评注、理由、用时、token、非法重选次数。能暂停、前后单步、点着法跳到任意一步，有键盘快捷键。
  - 已做（2026-09-30）：左边照搬窄版的棋手条 + 棋盘 + 棋手条（字号配色不变），棋盘边长随窗口高度（`100vh` 减上下留白、两条棋手条、顶部细条）；右边一栏从上到下是棋种（多盘时一个下拉框换盘）、双方全称与「思考深度」、结果，播放按钮（首 / 上一步 / 播放暂停 / 下一步 / 尾），着法列表（每回合一行，当前这步高亮，`?` `??` `?!` 标红、`!` `!!` `!?` 标绿），这步的详情（记谱、标注及其中文说法、将军、谁走的；用时、思考 / 输出 / 输入 token、缓存读写、非法重选、被拦截、空回复，各带中文标签，非零的异常次数用强调色；理由文字；不认识的命令原样列出），最底下一行快捷键提示。配色沿用窄版的变量，宽版自己的取值在 `app.css` 末尾「宽版」一节。
  - 快捷键：← → 单步（本盘到底再按 → 进下一盘，开头按 ← 回上一盘最后一步），空格 播放 / 暂停，Home / End 本盘首尾，PgUp / PgDn 上一盘 / 下一盘；点着法跳到那步。手动跳步先停下自动播放，再按播放从跳到的那一格往下播。跳到最后一步时直接带终局横幅。窄版（非 `rec=1`）也认这些键，只是没有右栏。
- 窄版（录屏用）：右侧整块不渲染，只剩页头、棋盘、页脚，细节见下一节「录屏画面」。
- 默认按窗口宽度自动切换（宽 ≥ 900 用宽版，窗口改大小时跟着切）；参数 `layout=compact` / `layout=wide` 强制。`rec=1` 恒为窄版（录 16:9 时页面宽 960，自动判断会判成宽版，所以录制不靠自动判断）。
- 两种版式都有：上一步高亮、被将军提示、终局结果和结束原因、可选的标题画面（默认不加，参数 `title=1` 开）。两种棋各照自己的主流软件画（见「棋盘」），不求统一。

**播放。**
- 自动播放（给人看、也给实时录窗口的备选用）：每步间隔默认 1.8 秒（含 0.3 秒走子滑动，落定后停 1.5 秒），可调；一盘播完放结果，再接下一盘；全部播完在页面上置「已播完」标记。多盘连播时，最后一盘的结果之后再加一格「总比分」画面（双方名字、总分；用户 2026-09-30 定），单盘不加。
- 录制模式（给脚本用，参数 `rec=1`，隐含 `layout=compact`、关掉计时器）：
  - `window.viewer.ready`：字体、棋子图、所有棋谱都加载完才兑现。
  - `window.viewer.next()`：前进一格，画完（再等两帧）才返回 `{kind, hold, anim, sound}`——`kind` 是 `title` / `move` / `result` / `end`（多盘时 `end` 这格画总比分；单盘没有这格画面，`end` 的 `hold` 为 0、不改画面），`hold` 是这一格该停几秒，`anim` 是走子动画的时长（没有动画为 0）。这格总长 = `anim` + `hold`：走子格 `anim` = min(`anim` 参数, `gap`)、`hold` = `gap` − `anim`，所以总长仍是 `gap`；其余格 `anim` 为 0。`anim > 0` 时 `next()` 兑现那一刻动画已开始、停在起点（录制脚本拨进度，见「录屏：脚本出片」）。`sound` 是这格响哪声：走子格吃子为 `capture`、否则 `move`，`result` 格为 `end`，其余 `null`；响在这格开头再过 `anim` 秒（见「走子音效」）。
  - 标题、结果画面停多久也由页面按参数给出，脚本只照 `hold` 办，不自己算。
- **一格一格的顺序**（实现在 `viewer/lib/play.js`）：每盘先是开局局面一格（`kind` 记 `move`、停 `gap`；`title=1` 时换成 `title`，标题画面盖在开局局面上、停 `titlehold`），然后第 1 到第 N 个半回合各一格 `move`（停 `gap`），这盘有结果（或读到一半读不懂）再加一格 `result`（终局横幅、比分加上这盘、「胜」）；全部盘之后是 `end`。走完最后一步那格还不出横幅、两边都不点亮，下一格 `result` 才出。
- **网址参数**（时长单位秒，不合法时用默认）：

  | 参数 | 默认 | 作用 |
  |---|---|---|
  | `files` | — | 逗号分隔的棋谱路径，一个文件可以有多盘；清单顺序就是第几局 |
  | `autoplay` | 0 | `1` 打开就自动播放；拖文件进来时默认直接播，`autoplay=0` 则只画第一格 |
  | `gap` | 1.8 | 每步（`move` 格）停多久，含走子滑动 |
  | `anim` | 0.3 | 走子滑动多久，算在 `gap` 之内（先滑 `anim`、再停 `gap − anim`；超过 `gap` 时按 `gap`）；`0` 关掉 |
  | `titlehold` | 3 | 标题画面停多久（`title=1` 时才有） |
  | `resulthold` | 4 | 终局横幅那格停多久 |
  | `summaryhold` | 5 | 多盘时总比分那格停多久（单盘的 `end` 恒为 0） |
  | `title` | 0 | `1` 每盘开局前加标题画面（`0` 或不给都不加；拖文件进来同样按这个） |
  | `vendor` | 1 | `0` 标题画面上名字前不补厂商（「GPT astra」→「astra」） |
  | `sound` | 0 | `1` 打开走子音效（看棋谱默认静音；`rec=1` 时页面不出声，由录制脚本混音） |
  | `vol` | 1 | 音效整体音量倍数（0.5 约轻 6 dB）；不大于 0 或不合法时为 1 |
  | `rec` | 0 | `1` 录制模式：隐含 `layout=compact`，不起计时器、不理 `autoplay` 和空格键，只听 `viewer.next()` |
  | `layout` | 自动 | `compact` 强制窄版，`wide` 强制宽版；不给按窗口宽度（≥ 900 为宽版）；`rec=1` 时恒为窄版 |
  | `game` / `ply` / `summary` | — | 静态看某一格（截图用）：第几盘（从 1 起）、半回合数或 `end`、`summary=1` 看总比分；和 `autoplay=1`、`rec=1` 同时给时不起作用 |

- **页面接口**：`window.viewer.ready`、`next()` 见上；播完（到了 `end` 那格）`window.viewer.done` 为 true、`body` 上置 `data-done="1"`，之后再调 `next()` 返回 `{kind: 'end', hold: 0, anim: 0, sound: null}`；`play()` / `pause()` 开关自动播放（空格键同样切换，播完再播从头来；其余快捷键见「版式」宽版）；`show(game, ply)`、`summary()` 直接画某一格。出错时 `ready` reject、`body` 上写 `data-error`。
- **标题画面**（用户 2026-09-30 定）：盖在开局局面上的一块卡片，多盘时第一行「第 i 局 · 共 N 局」（单盘没有这行），不写棋种；下面是双方全称（前面补厂商，如「Claude opus」「GPT astra」，认不出的照原名；网址参数 `vendor=0` 不补，录制用 `--set vendor=0`）与思考深度，红 / 白方在前、中间一个「对」。卡片两种棋一个样子：左右各离棋盘边 24（象棋棋盘比页面窄，按棋盘实际位置算）、圆角、一点投影；底色 45% 黑，和终局横幅相同，字带同样的阴影。赛制（三局两胜之类）棋谱里没有，不写。
- **拖文件进页面**：拖进来的几个文件按文件名排序，当作一场新的比赛从头播；没给 `files` 打开页面时显示拖放提示。

**棋盘。**
- 国际象棋：cm-chessboard 画棋盘（MIT，源码是相对路径引用的 ES 模块、无依赖，可直接放 vendor；已实测按网址参数读 g1 棋谱走完 95 个半回合、2 倍截图清晰）；chess.js 按记谱走子、判将军（BSD-2-Clause，用 npm 发布包里的单文件 `dist/esm/chess.js`，本机克隆只有 TS 源码不能直接用）。
  - 配色照 lichess 默认的 brown 主题：浅格 `#f0d9b5`、深格 `#b58863`（取自 lila 的 `public/images/board/brown.png`），上一步起止两格盖 `rgba(155,199,0,0.41)`，被将军的王所在格垫红色径向渐变（两者照 chessground 的 `chessground.brown.css`）。
  - 棋子不用 cm-chessboard 自带的（`standard.svg` 是 CC BY-SA 3.0、`staunty.svg` 禁商用），改用 Wikimedia Commons 上 Cburnett 的 12 个原件、取 BSD 许可（用户 2026-09-29 定），照 `standard.svg` 的结构拼成精灵图 `vendor/cm-chessboard/assets/pieces/cburnett.svg`；画面上不用署名。来源和生成脚本在 `vendor/cburnett-pieces/`。
- 中国象棋：棋盘和棋子都自己画成 SVG，照主流象棋软件的样子（用户 2026-09-30 要求；参照 xqbase 的象棋巫师截图与象棋小巫师 `xqbase/xqwlight` 的图片素材，腾讯天天象棋也是「经典木纹界面」）：浅木色棋盘、双线外框、炮位兵位画「花」、上下标路数（黑方 1–9 在上、红方 九–一 在下）；棋子是木色圆子，红方红字红圈、黑方黑字黑圈（红方俥傌相仕帥炮兵、黑方車馬象士將砲卒，象棋软件的常见写法）；上一步在起点和落点各画四个蓝色角框；被将军的将 / 帅外圈一圈红晕，被将死的变灰（象棋巫师的做法）。
  - 为什么不用素材：xiangqi-setup 里许可干净（CC0）的三套棋子都是实心红 / 黑圆底，不是主流样子；其余几套是 CC BY / CC BY-SA / 禁商用。原先那套 `vendor/xiangqi-pieces/`（playok，CC0）页面不再用，2026-09-30 已从仓库删除（来源与许可核对记录随之删除，要找回看删除前的提交）。
  - 棋子上的字用页面字体现画（楷体：`Kaiti SC` / `STKaiti` 等，本机是系统自带的），不拷任何字体文件，也不把字形描成路径，所以没有字体再分发的权利问题；代价是换一台没有楷体的机器会退回别的中文字体，出片在本机做，不受影响。第一帧之前用 `document.fonts.load` 等楷体就绪，本机冷启动重跑截图逐字节一致。
  - 自己写中文记谱解析（结合当前局面认出是哪个子）和将军判断，只为显示，不校验合法性。
  - 这是有意的例外：项目规定「规则判定照搬旧实现」，那是指对局程序判定输赢和合法性。阅读器只画面上提示「将军」，不影响任何结论，所以用 JS 自写；正确性靠与 `game.jsonl` 里（pyffish 判出的）将军标记逐步对照来保证。
- 两边共用一个自己写的 PGN 分词器（标签、着法、评注、标注、结果；变着先跳过不显示）。PGN 结构简单、规范写死，约一百行，比引一个只认国际象棋记谱的解析库省事。
- 走子动画（2026-09-30 已做，`lib/anim.js` 加两块棋盘各自的 `render`）：用 Web Animations（可以按进度定格，逐帧截图能录出滑动），缓动 `ease-in-out`，全都 `fill: none`——棋盘先画成走完的局面，动画只在上面「借」一段时间，结束或被 `finish()` 时元素回到本来的样子，什么都不用补。
  - 中国象棋：落点那枚子挪到最上层，从起点滑到落点；被吃的子另画一枚垫在最下层，动画期间可见、结束消失。
  - 国际象棋：cm-chessboard 自带的动画是 `requestAnimationFrame` 手写的（已读源码），不能定格，一直关着（`animationDuration: 0`）；在它画好的终局上叠一层：落点的真棋子动画期间透明，另叠一枚走之前的棋子从起点滑到落点（升变时滑的是兵、结束才是后），被吃的子（吃过路兵是旁边那格的兵）待到结束；王车易位时车同时滑。
  - 什么时候滑：自动播放和录制的每个走子格；宽版 / 窄版手工单步只在同一盘往前走一步时滑（往回、跳步、换盘直接画）；静态看某一格（`game` / `ply`）不滑。新一步开始（或换局面、改窗口大小）时上一段直接跳到终点，连按不丢步、不错位。自动播放每格等 `anim + hold` 秒。
  - 录制时（`rec=1`）动画一建好就暂停在起点，由脚本拨进度。静止画面（动画走完那一格）与不带动画时逐字节相同：临时叠上去的子在结束时从页面删掉。

## 走子音效

> 2026-10-02 做。先调研过主流软件在哪些事件发声、音量多大、哪些素材许可干净（调研原文是会话临时文件、没入库，要点收在本节）。

**用户已定（2026-10-02）**：
- 每步只响一声：吃子用吃子声，否则落子声；将军不单独配声；终局（结果横幅出现时）再响一声。两种棋共用一套。这和 lichess 默认套、xiangqi.com 的做法一致（它们也只有走子、吃子两种声，将军不出声）。
- 录视频默认有声；网页里看棋谱默认静音，网址参数 `sound=1` 打开。
- 声音落在棋子落地那一刻：这格开头再过 `anim` 秒（动画结束）；`anim=0` 时就是格的开头。终局声在结果格开头，也就是横幅出现那一帧。
- 音量照 chess.com 的量级，不对整条音轨做 −14 LUFS 归一化（稀疏的敲击声拉到 −14 会刺耳）。

**素材**：freesound 上 el_boss 的「Chess Puzzle Blitz SFX」包，CC0。落子用 Piece Placement（0.11 秒）、吃子用 Piece Capture（0.24 秒）、终局用同包的 Board Start（约 0.5 秒的一串木子碰撞，和单声的落子 / 吃子听得出不同）。原样存在 `viewer/vendor/sounds/`（`move.mp3` / `capture.mp3` / `end.mp3`，用的是网站公开的试听版，原件要登录才能下、同一许可），来源、许可核对、SHA-256 见同目录 `SOURCE.md`。没用的：lichess 的音效（许可不明或 AGPL / CC BY-NC-SA）、chess.com（专有）、vschess 与象棋小巫师（GPL / LGPL）。

**音量**：文件不改，增益写在 `viewer/lib/sound.js` 的 `SOUNDS` 表里（页面播放和录制混音共用这一份）。「单声响度」是补静音到 1.5 秒后量的 EBU R128 integrated（不到 400 ms 的音直接量会报 −70）。

| 声音 | 原始峰值 / 单声响度 | 增益 | 成片里约 | 依据 |
|---|---|---|---|---|
| 落子 `move` | −12.2 dBFS / −32.7 LUFS | +1.7 dB | −10.5 dBFS / −31.0 LUFS | chess.com 落子峰值约 −6 到 −10、响度约 −33 |
| 吃子 `capture` | −2.3 / −20.6 | −7.9 dB | −10.2 / −28.5 | 比落子高 2.5 dB（chess.com 吃子高 2–3 dB） |
| 终局 `end` | −6.6 / −25.2 | +0.7 dB | −5.9 / −24.5 | 比吃子再高 4 dB（要求 3–6 dB） |

整体音量倍数：网址参数 `vol`、录制 `--vol`（默认 1，0.5 约轻 6 dB）。几声叠在一起超过满刻度时削到 ±1（默认音量下各声峰值都在 −5 dBFS 以下，正常间隔碰不到）。

**页面**（`app.js`「走子音效」一节）：`sound=1` 时载入就用 Web Audio 读好三个文件（不挡 `ready`，没读好那一声就不响、只在控制台警告）；每声按表里增益乘 `vol` 过一个增益节点，用 `start(当前时刻 + anim)` 排到落地那一刻。自动播放每格都响；手工操作只有「同一盘往前走一步」响这步的声，以及停在最后一步还没出横幅时再往前（补出终局格）响终局声；往回、跳步、换盘不响。浏览器的自动播放限制：页面上没点过、没按过键时音频挂起，第一次点击或按键时恢复，所以 `autoplay=1&sound=1` 打开后要先点一下页面才听得到。界面上没加开关，只靠网址参数。

**录制**（`record.mjs`）：页面在录制模式下不出声，`next()` 只报这格的 `sound`。脚本在截完这格的动画帧、截静止画面之前记一个「从第几张截图开始响」；出片时按和画面同一套累计帧数（`toFrames`）算出每声的时刻（第 i 张从第 Σ帧数 帧开始，就从那一帧的时刻响），所以声画不会因取整错位。三个文件用 ffmpeg 解码成 48 kHz 单声道浮点样本，在 Node 里按时刻叠进一条与视频等长的缓冲区（尾巴超出片长截掉），写成原始 `f32le` 作为 ffmpeg 第二路输入，编码成 AAC 128k、48 kHz、单声道（素材本来就是单声道；转双声道时 ffmpeg 默认每路压 3 dB，原样复制又让 LUFS 读数多 3 dB，单声道出片的峰值、响度才和上表一一对得上，手机外放照样两个喇叭都响）。不在 ffmpeg 里用 `adelay` + `amix`：几百步时滤镜图很大，而且 `amix` 默认按输入数压音量。`--no-sound` 时照旧 `-an`、没有音轨。

**实测**（2026-10-02，默认 gap 1.8、anim 0.3）：
- 音画对齐：国际象棋 `b1-ch-session-1`（43 步）整盘出片，44 声的解码起点比各自该响的时刻（格开头 + 0.3 秒，即落定那一帧）晚 7.4–27.8 ms：落子 7.4、吃子 10.4、终局 27.8，全是素材开头自带的静音，不到一帧。抽第 8、13 步（都是吃子）逐帧比对：落定帧在 14.700 / 23.700 秒，声音起点 14.7105 / 23.7104 秒；`ease-in-out` 收尾慢，动画最后一张（落定前一帧）棋子已走完约 98%、肉眼几乎看不出还在动，所以听感上声音比「看着停下」晚一帧左右，在可接受范围（没为此提前）。
- 音量：两段样片（上面那盘国际象棋、象棋 `g5-x-astramax-opus-2` 46 步）每声峰值落子 −10.6、吃子 −10.2、终局 −5.9 dBFS，与上表一致；整条音轨 integrated −29.6 / −29.7 LUFS（门限把静音段滤掉后的读数，只作参考，不拿它定音量）。测试：`viewer/test/sound.test.js`（每步响哪声、增益量级、网址参数；录制模式下 `next()` 的 `sound` 与棋谱吃子逐格一致、页面不读声音文件；默认不出声；`sound=1` 自动播放和手工单步响对的声、延迟等于 `anim`）、`record.test.js` 加的几条（声音时刻、混音、默认有 AAC 音轨且时长同画面、每声起点对上落地时刻、`--no-sound` 没音轨）。

- **谁执哪方**：棋手条贴着自己那一方的棋子——执黑的在棋盘上方，执红 / 白的在下方（棋盘固定红 / 白在下）；名字前再加一个小圆片（红 / 黑 / 白）。位置加颜色双重提示，不用写「执红」这样的字。
- **每条两行，每行只有左右两样东西**：
  - 第一行：圆片 + 「模型简称+思考深度」（24，`+xhigh` 弱一档颜色）……右端本场比分（28，粗体，单盘时不显示）。名字太长时从名字中间省略，思考深度和比分不截。
  - 第二行（16–18，弱色）：左边是这位棋手刚走的一步（带回合数；将军时后面加「将军」小标签。回合号：国际象棋黑方照标准写「11... Nf6」；中国象棋黑方不带省略号，写「11. 马３退２」，宽版着法详情同样——用户 2026-09-30 定，只改显示，PGN 导出与解析不动），右边是思考 token（见下条）。
- **比分跟着人走**：换先后时两人上下对调，比分写在各自的条上，所以不会对错人。
- **该谁走**：轮到的一方整条点亮（亮一档的底色 + 左边一道强调色竖条），另一方压暗。走完一步的瞬间：刚走的一方第二行更新成这步和这步的 token，然后对方那条亮起来。
- **思考 token 的写法**（用户定：简化、大家看得懂就行）：「思考 52k +3.4k」——前面是含这一步在内的累计，后面小一号、强调色的 `+3.4k` 是这一步想了多少。增量只挂在刚走完的那一方；另一方只显示累计。选「当前累计 + 本步增量」而不是「此前累计 + 本步」：累计是主数字，含义始终是「到现在一共想了多少」，增量做成角标样式，不会被读成要再加一次。

## 中国象棋棋谱格式

象棋没有国际象棋 PGN 那样一家独大的格式，常见的几种：

| 格式 | 样子 | 用在哪 |
|---|---|---|
| 中文纵线记谱 | `炮二平五 马８进７` | 比赛记录、书籍、人读的棋谱，最通行 |
| WXF 记谱 | `C2.5 H8+7` | 中文记谱的字母版，国际上用 |
| ICCS 坐标 | `h2e2 h9g7` | 程序之间用，写起点和终点格子 |
| xqbase PGN | 照搬国际象棋 PGN 的结构，着法可用上面三种之一 | 象棋软件和网站的通用交换格式之一 |
| 东萍 DhtmlXQ、象棋桥 XQF | 网页插件格式、桌面软件的二进制格式 | 东萍网站、象棋桥等软件 |

**选 xqbase PGN + 中文记谱**，理由：中文记谱是人读的标准写法；xqbase PGN 是有公开规范的文本格式，结构和国际象棋 PGN 一样，两种棋可以共用一个分词器。

**标准本身没有歧义。** 之前说的「几个兵在同一列写不准」是本项目现在用的记谱库（cchess）的毛病，不是标准的：规范对同线多子、多路兵都规定了写法，并声明就是为了从棋局到着法完全消除歧义。所以导出端照规范自己生成记谱即可，阅读器照规范解析。

**我们要多记的东西，标准都留了口子，属于兼容扩展**（和国际象棋 PGN 的做法一样）：
- 每步理由和 token：写在着法后的 `{}` 评注里，规范说评注允许任意字符；我们的 `[%think 34]` 这类命令对别的软件就是一段普通文字。
- 思考深度：自定义标签 `RedEffort` / `BlackEffort`。PGN 允许自定义标签，读不懂的软件会忽略。

没有需要另起格式的地方。

**以后的网站看盘服务**（用户 2026-09-29 提）：棋谱要能带上每步的棋评和元信息，让网站按需组织呈现。现在的写法已经满足：每步评注里命令（`[%名 值]`，机器可读）和文字（理由、agent 加的棋评）分得开，网站可以把数字做成图表、把文字按类排版。为此要守住一条：**自定义命令的名字和含义就是对外契约**，真身在 `design.md` 第四节，新增命令（比如以后 agent 写大失误标记）先在那里登记，别各处各起名。

## 录屏：脚本出片

之前怎么录的（post-studio 调研，`viewer-survey/post-studio-recording.md`）：已发布的 007、008 是 ChatGPT 桌面端操作真 Chrome、把窗口拖窄，用 macOS 自带的 `screencapture` 录屏幕上那块区域，再剪辑。后来 post-studio 自己做了只录单个窗口的工具（`recwin.swift`）和剪辑脚本（`media.py`）。踩过的坑：锁屏时录了近 10 分钟锁屏壁纸；录像窗口被关、正式赛两度中断；agent 光标和提示条叠进画面；思考时画面长时间静止只能加速；录出来是变帧率要转码。发布比例后来定为 **3:4、1080×1440**（9:16 在小红书会被裁窄）。

**做法。** 录制脚本（Node + playwright-core，放 `viewer/record.mjs`）：
1. 自己起、关一个绑本机的静态服务。站点根是个空目录，只供给 `/viewer/` 和命令行点名的那几个棋谱文件（映射成 `/rec/1.pgn`…），棋谱可以在本机任何地方，所在目录的其他文件不外露。
2. 无头浏览器打开 `/viewer/?rec=1&files=…`，视口 540×720、2 倍像素（= 1080×1440；9:16、16:9 换视口尺寸即可）。
3. 等 `viewer.ready`，循环调 `viewer.next()`：静止画面截一张、记下 `hold`；有动画时按 1/30 秒逐格拨进度逐格截图。**动画的约定**：`anim > 0` 时 `next()` 兑现那一刻动画已经开始、暂停在起点；脚本对 `document.getAnimations()` 逐格设 `currentTime`（0、1/30 秒…共 `round(anim×30)` 格，各张秒数合起来恰为 `anim`），截完调 `finish()` 再等两帧，截静止画面停 `hold`。这一格总长 = `anim` + `hold`，页面给的走子格 `hold` 已是 `gap − anim`，所以动画不拉长视频（用户 2026-09-30 定）；`--anim <秒>` 改动画时长，`--anim 0` 关掉。
4. 写 ffmpeg concat 列表（最后一张重复写一次，否则它的时长被忽略），拼接后截到应有长度（实验里末尾多出约 0.3 秒）。实际做法：各格秒数按累计时刻取整成帧数（总帧数 = round(总秒数×30)，误差不随格数累积），用 `-frames:v` 截到这个帧数，比 `-t` 更准。

**输出规格**（和 post-studio `media.py` 的默认一致，拿去剪辑、上传不用再转）：mp4 封装，H.264（libx264，High），yuv420p，30 帧恒定帧率，`+faststart`，默认 1080×1440；音轨 AAC 128k、48 kHz、单声道（`--no-sound` 时没有，见「走子音效」）。ffmpeg 用 Homebrew 的（Playwright 缓存里带的那个在本机跑不起来）。颜色：截图是全范围 RGB，转换时显式用 bt709 矩阵转成有限范围 yuv420p，并在码流里标 bt709（实验命令只标了没指定矩阵，ffmpeg 默认按 bt601 转，颜色会偏；而且本机 ffmpeg 9 实测 `-color_primaries` 这类输出选项没生效、被滤镜输出的帧属性盖掉，要在滤镜里用 `setparams` 标）。

**相比实时录窗口**：不用屏幕录制权限，不怕锁屏、窗口被挡或被关，用户同时用 Mac 也不受影响；每步时长分毫不差、不丢步、没有空等；画面里只有棋局；比实时快，同一盘录几次结果一样，可以批量出片。

**写 / 测代价：低，录两三次就回本。** 核心流程调研时已在本机跑通：35 行的实验脚本（`viewer-survey/record-experiment/exp_frames.js`）用 playwright-core 加本机缓存的 Chromium 逐帧截图、带走子动画，ffmpeg 合成出了 1080×1920 和 1920×1080 的 H.264 视频，两次渲染逐帧一致。正式脚本多出起服务、调页面接口、截尾，估计 100–150 行，写加测约半天 agent 时间。之后每次出片一条命令，几分钟跑完，不用人看着，不耗模型额度。实时录窗口每次都要 Mac 解锁、按实际时长干等、先试录核对不是锁屏画面、事后剪辑转码。

**备选：实时录窗口。** 页面在普通 Chrome 窗口里本来就能自动播放，post-studio 那套（`recwin.swift` + `media.py`）直接可用。脚本万一卡住就退回这条，阅读器不用改。

注：Playwright 自带的录像功能（recordVideo）不用——按网页逻辑尺寸录，放大后画面只占一角，帧率固定 25、码率低、格式 webm（本机实测，`viewer-survey/recording.md`）。

**用法**（`node viewer/record.mjs --help` 同样内容）：

```
node viewer/record.mjs [选项] <棋谱> [<棋谱> …] -o <输出.mp4>
node viewer/record.mjs ~/repos/llm-chess/runs/g1-c-opus-sol -o /tmp/g1.mp4                 # 单盘，默认时长
node viewer/record.mjs runs/a/game.pgn runs/b/game.pgn -o /tmp/ab.mp4 --gap 1.5 --title     # 连播加标题画面，末尾总比分
node viewer/record.mjs runs/g1-x-opus-sol -o /tmp/g1x-916.mp4 --aspect 9:16
```

| 参数 | 默认 | 作用 |
|---|---|---|
| `<棋谱>` | — | 本机任意路径，可多个，按给出顺序连播；给目录时取其中 `game.pgn` |
| `-o` / `--out` | 必填 | 输出 mp4；目录须已存在；先写同目录临时文件，成功再改名 |
| `--gap` / `--titlehold` / `--resulthold` / `--summaryhold` | 页面默认（1.8 / 3 / 4 / 5） | 透传给页面同名网址参数；脚本不自己算时长，只照 `next()` 的 `hold` |
| `--title` | 无标题 | 透传 `title=1`，每盘开局前加标题画面 |
| `--no-title` | — | 等同默认（不加标题），留作兼容旧命令 |
| `--aspect` | `3:4` | `3:4` 视口 540×720、`9:16` 540×960、`16:9` 960×540 |
| `--scale` | 2 | 像素倍数（3:4 默认出 1080×1440） |
| `--set 名=值` | — | 再透传任意网址参数（可多次）；`rec`、`files` 由脚本给，不许改 |
| `--vol` | 1 | 音效整体音量倍数（正数；0.5 约轻 6 dB），见「走子音效」 |
| `--no-sound` | 有声 | 不要音效，出无声视频（没有音轨） |
| `--chromium` | `VIEWER_CHROMIUM`，再默认 playwright-core 配套的缓存浏览器 | 浏览器可执行文件 |
| `--ffmpeg` | `VIEWER_FFMPEG`，再默认 `/opt/homebrew/bin/ffmpeg` | ffmpeg |

成功时打印时长、帧数、截图张数、各类格数和用时；失败打印中文原因、退出码 1；Ctrl-C / SIGTERM 时先杀 ffmpeg、关浏览器和服务、删中间帧和半截输出再退（退出码 130）。开工前先查完棋谱、输出目录、ffmpeg、浏览器路径、画幅，查不过不起浏览器。

**实测**（2026-09-30，本机）：出片耗时主要花在截图（每格约 0.1–0.15 秒）和编码（按视频长度），默认时长下约每分钟视频 6 秒（国际象棋 95 步、244.5 秒视频用时 24 秒；象棋 33 步、89.5 秒用时 9.5 秒）。9:16 每张图大、稍慢。测试 `viewer/test/record.test.js`：自带样例、停留时长调小，ffprobe 核对编码、帧率、分辨率、faststart、时长；没有浏览器或 ffmpeg / ffprobe（`VIEWER_FFPROBE`，默认与 ffmpeg 同目录）时跳过。

**开发期依赖。** `viewer/package.json` 只放 playwright-core，**锁精确版本 1.58.2**：它配套的正是本机缓存里的 chromium-1208（1.58.0–1.58.2 都是 1208，1.59 起换 1217），不用下载浏览器。缓存里没有配套浏览器的机器，用环境变量 `VIEWER_CHROMIUM` 指到任一 Chromium / Chrome 可执行文件。`.gitignore` 加 `node_modules/`。

## 仓库里的配套改动（`llmchess/`）

- **PGN 标签补思考深度**：国际象棋加 `[WhiteEffort "xhigh"]` / `[BlackEffort …]`，取自 `game.jsonl` 的 `config`（双方用的深度）；非模型方（引擎、随机）不写。
- **中国象棋导出 PGN**（`game.pgn`，和 `record.txt` 并存）：标签 `Game`（第一个）、`Event`、`Red`、`Black`、`RedEffort`、`BlackEffort`、`Result`、`Termination`（沿用现在的中文结束原因）；评注写法和国际象棋一致。
  - **着法文字**：现有中文记谱（cchess 库）在多路兵、同线三个以上同种子等少见局面写不准，会在后面补「（坐标）」，出异常时直接写坐标（`llmchess/xiangqi.py` 的 `notation`）；这种写法进 PGN 就没法解析。PGN 导出改为按 xqbase 规则生成中文记谱（从局面和坐标算，只是记谱格式，不涉及棋规）；`record.txt` 保持原样，旧记录照旧复现。现有 135 盘已结束的象棋对局里一次都没碰到这类局面，所以要另造多路兵、同线多兵的局面测往返。
- **中文折行**：现在导出会在中文字中间断行，任何阅读器读回来断开处都多一个空格。改法：优先在空格或中文标点后断行，实在没有才硬切；阅读器读的时候，两边都是中文的断行不补空格。（已实施：中文串里只在两个全角字符之间断，「中文」按 Unicode 东亚宽度 W / F 判；阅读器照同一判法。断点优先级：中文标点后 > 其余空格 > 两个中文字之间硬切；「中文 空格 中文」里的空格永不作断点，否则按上面的读法会少一个空格，第一版漏了这条，本机 424 步中招，已修并重导。取舍：硬切在两个中文字之间时，我们的阅读器读回正好，别家 PGN 阅读器会多一个空格，可以接受——修之前本来如此，且只在没有标点可断的长串出现。往返由 `viewer/test/wrap.test.js` 和读 runs 的回归逐字核对。）国际象棋不走 `meta_comment`，要改的是评注拆词和折行那两处（`meta_tokens`、`wrap`），两种棋共用。
- 已结束的盘用 `python3 -m llmchess export runs/<tag>` 重导（只重写导出文件，不动 `game.jsonl`）。批量重导只挑记录里有 `end` 那一行的盘，导不出的跳过并计数；别碰正在下的对局。
